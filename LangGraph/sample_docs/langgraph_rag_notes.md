# LangGraph 与 RAG 学习笔记

## LangGraph 基础

LangGraph 是一个用于构建有状态 AI 工作流和 Agent 的框架。它使用图结构来表达流程，核心概念包括 State、Node、Edge 和 Graph。State 表示图运行时共享的数据，Node 表示处理步骤，Edge 表示节点之间的流转路线，Graph 表示完整工作流。

LangChain 更偏向提供组件，例如模型、提示词、工具、检索器和输出解析器。LangGraph 更偏向流程编排，例如状态传递、条件分支、循环、持久化和人工介入。真实项目中经常把 LangChain 组件放进 LangGraph 节点中运行。

## Workflow 与 Agent

Workflow 是固定路径的工作流，适合流程明确、步骤稳定的任务。例如内容生成可以分为生成大纲、写初稿、润色文章三个节点。

Agent 是由大模型动态决定下一步的智能体，适合开放问题和多步骤推理任务。Agent 可能会先调用模型判断是否需要工具，如果需要就调用工具，工具返回后再回到模型继续推理，直到生成最终答案。

## RAG 基础

RAG 是 Retrieval-Augmented Generation，也就是检索增强生成。它的目标是让模型基于外部知识库回答问题，减少幻觉并补充模型训练数据中没有的私有知识。

典型 RAG 流程包括：加载文档、切分文本、生成向量、存入向量库、根据用户问题检索相关片段、把问题和片段放入提示词、调用模型生成答案、解析输出。

## Agentic RAG

代理式 RAG 不是每次都固定检索，而是让模型先判断是否需要检索。如果问题可以直接回答，模型可以直接响应；如果问题需要知识库支持，模型会调用检索工具。

一个常见的代理式 RAG 图包括四个节点：决策节点 generate_query_or_respond、检索工具节点 retrieve、问题重写节点 rewrite_question、答案生成节点 generate_answer。

决策节点负责决定是直接回答还是调用检索工具。检索节点负责执行 Retriever Tool。相关性评分节点会判断检索到的文档是否能回答问题。如果相关，就进入答案生成节点；如果不相关，就进入问题重写节点，改写查询后再次回到决策节点。

## 检索质量

RAG 效果很大程度取决于检索质量。影响检索质量的因素包括文档切分方式、chunk_size、chunk_overlap、embedding 模型质量、向量库搜索策略、top_k 数量和查询改写能力。

如果检索结果不相关，模型应该避免强行回答。更稳妥的做法是先重写问题再次检索，仍然没有足够资料时回答“资料中没有足够信息”。

## LangGraph 持久化

LangGraph 支持 checkpoint 机制，可以根据 thread_id 保存和恢复图的状态。持久化让多轮对话、长任务、中断恢复和人工介入成为可能。

短期上下文通常保存在 messages 中。长期记忆可以保存到数据库、Redis 或向量库中。运行时不一定把所有历史都传给模型，而是选择最近消息、摘要和检索到的相关记忆组成上下文。
